# « Banana-in-box » invalide

Ce diagnostic détecte une syntaxe « banana-in-box » inversée pour les [two-way bindings](guide/templates/two-way-binding).

```html
<user-viewer ([user])="loggedInUser" />
```

## Quel est le problème ? {#whats-wrong-with-that}

En l'état, `([var])` est en réalité un [event binding](guide/templates/event-listeners) nommé `[var]`.
L'auteur voulait probablement écrire un two-way binding vers une variable nommée `var` mais, tel qu'il est écrit, ce binding n'a aucun effet.

## Que faire à la place ? {#what-should-i-do-instead}

Corrigez la faute de frappe.
Comme son nom l'indique, la banane `(` doit se trouver _à l'intérieur_ de la boîte `[]`.
Dans ce cas :

```html
<user-viewer [(user)]="loggedInUser" />
```

## Prérequis de configuration {#configuration-requirements}

[`strictTemplates`](tools/cli/template-typecheck#strict-mode) doit être activé pour qu'un diagnostic étendu soit émis.
`invalidBananaInBox` n'a pas d'autre prérequis que `strictTemplates`.

## Et si je ne peux pas l'éviter ? {#what-if-i-cant-avoid-this}

Ce diagnostic peut être désactivé en modifiant le fichier `tsconfig.json` du projet :

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "invalidBananaInBox": "suppress"
      }
    }
  }
}
```

Consultez la [configuration des diagnostics étendus](extended-diagnostics#configuration) pour en savoir plus.
